# Project Brief: metranom-pro

## Суть (как есть сейчас)
Статический веб-метроном без бэкенда и сборки: чистые HTML/CSS/JS, деплой — просто файлы
(репозиторий на GitHub `gooozmen/metranom-pro`). Пользователь задаёт темп (слайдер/поле/TAP),
собирает очередь тактов (размер N/4, N/8, N/16), запускает воспроизведение — Web Audio API
планирует клики с акцентом на первую долю каждого такта, идёт визуальная подсветка активного
такта и текущей доли. Есть выбор звукового набора (acoustic/electronic) и переключатель
светлой/тёмной темы. Мобильная и десктопная раскладка отличаются (контролы телепортируются
между `.settings-panel` и `.bottom-section` по ширине окна).

## Пользователь и сценарий
Публичный сайт — открытый доступ для любого пользователя в браузере, разово или на постоянной
основе (музыканты, репетиции, обучение).

## Что меняем в этом цикле
Многослойный метроном: несколько независимых слоёв тактов, звучащих одновременно (полиритмия,
наложение партий и т.п.).

- **Подложка** — контейнер, вмещающий очередь тактов одного слоя (то, что сейчас единственная
  `.time-signature-queue`). Слоёв может быть несколько, каждый в своей подложке.
- Рядом с подложками — кнопка «+», создающая новую **абсолютно чистую** подложку с одним
  тактом 4/4 по умолчанию.
- Подложки размещаются в общей области **тайлингом** (автозаполнение доступного пространства,
  как в тайлинговых оконных менеджерах — i3/sway), без свободного позиционирования.
- **Перетаскивание** подложки на другую подложку **меняет их местами** (тайл-своп), а не
  двигает мышью в произвольную точку.
- **Темп**: по умолчанию все слои играют на общем глобальном BPM; у каждого слоя есть
  возможность включить собственный независимый темп, переопределяющий глобальный.
- **Звук и акцент**: по умолчанию общий набор (acoustic/electronic) и общий чекбокс
  «акцент на первую долю» действуют на все слои; у каждого слоя есть возможность
  переопределить их локально.
- **Запуск**: одна общая кнопка Play/Stop стартует и останавливает воспроизведение всех
  слоёв одновременно (единый момент старта `t0`; дальше слои живут по своему темпу/тактам
  независимо, отсюда и полиритмический эффект).
- Каждый слой сохраняет свою текущую механику: очередь тактов с +/- размером, визуальные
  точки-доли, подсветка активного такта.
- У каждой подложки должна быть возможность удаления (по аналогии с существующим
  удалением такта `×`), иначе слои, добавленные по ошибке, нечем убрать.

## Скоуп
**В скоупе:**
- Модель данных: от одного глобального `timeSignatureQueueState` — к массиву слоёв,
  каждый со своей очередью тактов, опциональным переопределением темпа/звука/акцента.
- Планировщик Web Audio API, запускающий несколько независимых цепочек `scheduler()`
  (по одной на слой) синхронно от общего `t0`.
- UI: контейнер-тайлинг для подложек, кнопка добавления слоя, drag-and-drop своп позиций,
  элементы переопределения темпа/звука/акцента на уровне подложки, удаление слоя.
- Адаптация под мобильную раскладку (тайлинг на маленьком экране — вертикальный стек).

**Вне скоупа (non-goals):**
- Сохранение пресетов между сессиями (localStorage) — не запрашивалось, отдельная фича.
- Независимый Play/Stop по слоям — явно отклонено пользователем в пользу общей кнопки.
- Свободное (не тайловое) перетаскивание мышью.
- Изменение звуковых файлов/добавление новых наборов звука.
- Бэкенд, синхронизация между устройствами, авторизация.

## Стек и окружение
Ванильный HTML/CSS/JS (ES6+), без сборщика и без зависимостей. Браузер — целевая среда
выполнения. Web Audio API (`AudioContext`, `decodeAudioData`, `AudioBufferSourceNode`).
Никакого пакетного менеджера, тестового фреймворка и CI в репозитории нет.

## Ограничения и риски
- **Полиритмия ломает предположение «один глобальный `currentTime` — один `scheduler`»**:
  текущий код держит один `scheduler()`/`nextNoteTime`/`notesInQueue` на весь метроном.
  Переход на массив слоёв с независимым темпом требует размножить это состояние на слой.
  Закрывается на стадии 4 (контракты) — риск архитектурный, не требует спайка (поведение
  Web Audio API с несколькими независимыми `setTimeout`-планировщиками одновременно —
  известная, не рискованная техника).
- **Drag-and-drop тайл-своп без библиотек** — нативный HTML5 Drag and Drop API достаточно
  прост для простого свопа двух элементов; если по ходу реализации всплывут неочевидности
  (мобильный тач, доступность), решается на стадии 7, не требует спайка заранее.
- **Дрейф между слоями с разным темпом на длинной сессии** — накопление ошибки округления
  double во времени `nextNoteTime` за много тактов теоретически возможно, но при разумной
  длительности сессии метронома (минуты, не часы) несущественно; принято как есть.

## Как запускать
Сборки нет. Открыть `main.html` в браузере. Для корректной работы `fetch()` аудиофайлов
(`sepls/.../*.mp3`) через `file://` возможны ограничения CORS в некоторых браузерах —
рекомендуется поднять локальный статический сервер из корня проекта, например:
```
python3 -m http.server 8000
```
и открыть `http://localhost:8000/main.html`. Тестов и команд запуска тестов нет.

## Глоссарий
- **Такт (measure)** — единица `{steps, unit}`: `steps` — число долей, `unit` — длительность
  доли (4/8/16), как в музыкальном размере N/unit.
- **Слой (layer)** — независимая дорожка метронома: своя очередь тактов, своя подложка,
  опционально свой темп/звук/акцент.
- **Подложка** — визуальный контейнер одного слоя, вмещающий его очередь тактов (карточки
  `.measure-card`).
- **Тайлинг** — авторазмещение подложек по доступному пространству без свободного
  позиционирования; перетаскивание меняет местами позиции двух подложек.
